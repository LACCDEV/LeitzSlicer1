# LEITZ Slicer 1 — TPE Lattice Cushions (Prusa XL)

A fully client-side, browser-based FDM slicer for designing **beautiful, airy
TPE cushions**: fill an STL with a lattice, wrap it in a **parametric perforated
outer shell that visually and structurally merges with the lattice**, and export
**surface-quality, stringing-optimized G-code** for the **Prusa XL**.

No backend, no build step — it's a static site you can host on GitHub Pages.

![3-panel layout: parameters · 3D viewport · G-code](https://img.shields.io/badge/stack-vanilla%20JS%20%2B%20three.js-0ba23b)

## Features

### STL import & display
- Drag-and-drop (or click-to-browse) import of **binary and ASCII** STL files
- Three.js viewport with orbit controls (Z-up, printer convention)
- Live bounding-box dimensions, triangle count, and volume
- Part is auto-centered on the 360 × 360 bed and rested on Z = 0 — the preview
  matches exactly where the G-code places it
- **Re-orient the imported object** on the bed (X/Y/Z sliders + reset) — rebuilds
  the inside-test sampler so all geometry follows
- **Cushion form generators** (no STL needed): **round disc** (Ø × H), **oval
  pad** (W × D × H), **rounded rectangle** — sized for ≤ 15 cm wearables

### Surface Studio — perforated & textile skins (`ShellGenerator.js`)
The skin is generated by planar slicing + a signed **hole field**: every point
around each layer's contour is tested wall-vs-hole, so the pattern follows
arbitrary surfaces and prints supported. A categorised picker + a live
**Printability meter** (0–100, span/feature/recommended-speed/warnings) drive it.

| Group | Patterns |
|-------|----------|
| **Knit / textile** | **Rib Knit / Micro-Rib** (fine vertical/diagonal ribs); **3D Woven mesh** (real interlacing warp + weft strands, below) |
| **Mesh / sport** | **Hex mesh**, **Circular array**, **Sine / interlock mesh** (±45° woven strands), **Voronoi organic** |
| **Structural** | **Auxetic** (re-entrant honeycomb — negative-Poisson), **Lattice-matched** |
| **Gyroid-matched** | **Gyroid-matched (flowing)** (phase-locked TPMS skin), **Node shell** (strut exits) |
| **Plain** | Solid, None |

Controls: hole size/pitch/shape, min wall, perimeters, taper, rotation, jitter,
scale gradient; rib width/gap/angle; mesh angle/strand/opening; auxetic
cell W×H / re-entrant / wall. A **Surface↔interior transition** macro (hard /
gradient / eruption / strut-anchor) and a **🎲 Surprise me** button round it out.

> Most patterns above are exact 2-D (arc, height) wall/hole textures. The
> **3D Woven mesh** is the exception — a true 3-D textile.

### 3D Woven mesh (`WovenSurface.js`)
A genuinely three-dimensional woven skin (not a flat texture): two strand
families that **interlace over and under** along the surface normal.
- **Warp** strands run vertically (one per arc slot — print clean);
- **Weft** rings run around the perimeter at each pitch (bridge between warp).
- At every crossing the families are anti-phase (cosine), amplitude ≈ a strand
  radius, so warp and weft **touch and bond**; which one is outside alternates
  by the **weave pattern** — **plain**, **twill**, or **basket**.

Airy controls: warp count, weft pitch, strand Ø, weave depth, pattern. Verified
≈97 % open / airflow-resistance 3 (very breathable).

> True 3-D *relief* patterns (bubble domes, scale armor, cable knit, flyknit,
> raised jersey loops) remain out of scope — a single-wall planar contour slicer
> has no per-bead Z; the woven mesh achieves 3-D by being **struts**, not a skin.

### Shell ↔ lattice merge
A single **merge intensity** slider makes the shell and lattice read as *one*
structure rather than a skin over infill:
- **Weld** — any strut that reaches the surface forces wall there, so struts
  always connect to the skin instead of floating into a hole
- **Transition thickening** — struts fatten as they approach the wall (extra
  extrusion on the near-surface segments)
- **Node blends** — small fillet loops deposited where struts meet the skin

### Beautiful preview
- **Shell opacity** slider — see the lattice through a translucent envelope
- **Colour modes** — *stress* (strut angle, amber = stringing risk → green),
  *print-risk* (strut angle bands: red < 30° / yellow 30–60° / green > 60°),
  *density* (material proxy), *design* (clean near-white)
- **Cross-section clip plane** — drag a cut through X / Y / Z (world-space)
- **Auto-rotate** turntable
- **Stats** — estimated material (g), print time, **stringing-risk score
  (0–100)**, **open-volume %** (how airy), **airflow-resistance score** (0 = open
  air, 100 = solid; target < 25 for summer wearables), segment count, **hole-area %**

All view changes recolour / clip / spin **in place** — they never regenerate
geometry.

### Presets, printability & calibration
- **Built-in presets**: the lattice/gyroid sets plus textile/wearable combos —
  *Knit Pillow* (gyroid + Micro-Rib), *Sport Pad* (skeletal + hex mesh), *Bio
  Cushion* (gyroid + voronoi), *Tech Object* (skeletal + auxetic), *Foam Pad*
  (Kelvin + rib) — plus save / export / import (JSON) of your own
- **Printability check** — flags impossible combos as errors (wall < nozzle,
  oversize bed) and quality risks as warnings (thin struts, holes that blob
  shut, etc.), all relative to the configured nozzle Ø
- **Tooltips** on every parameter explaining its print-quality effect
- **One-click Pressure-Advance tuning tower** — a standalone calibration print
  that steps the K-factor up its height

### Export
- **`.gcode`** — the print file for the Prusa XL.
- **`.obj` (toolpaths → filament beads)** — every printed path is swept into a
  round tube sized from its extrusion area, written as a Wavefront OBJ so you
  can drop it into **KeyShot** (or any DCC) and render the part *as it prints*.
  A "tube sides" control trades smoothness for file size; a built-in size guard
  keeps very dense models from producing an unusable file.

### Lattice generator (clipped to the model interior)
| Type | Description |
|------|-------------|
| **Simple cubic** | axis struts along X/Y/Z cell edges |
| **BCC** | body-diagonal struts only — best for flexible TPE |
| **FCC** | face-diagonal strut network |
| **Kelvin** | truncated-octahedron tiling — the closest printable open-cell-foam structure |
| **Gyroid — sheet** | the TPMS minimal surface, printed as a thin continuous wall (Marching Cubes) |
| **Gyroid — skeletal** | thin **curved** ligaments of the gyroid channel (ridge-following, not faceted chords) |

Cell size, strut diameter (↔ infill density), orientation, and top/bottom solid
layers are all live.

### Two gyroid modes (`Gyroid.js`, `LatticeGenerator.js`)
Both selectable as infill, sharing a **Gyroid options** panel:

- **Sheet** — `sin(x)cos(y)+sin(y)cos(z)+sin(z)cos(x)=iso`. Params: **cell period**
  (5–40 mm), **wall thickness** (printed bead width), **iso-offset** (asymmetric
  interlocking channels), **per-axis phase X/Y/Z** (diagonal orientation), and a
  **thickness gradient** (stiffer base / softer top).
- **Skeletal** — the channel medial axis, extracted numerically: the field's
  local maxima inside a channel become degree-≈3 **nodes**, connected by **thin
  curved ligaments** that follow the channel ridge (gradient-ascent perpendicular
  to the chord) so they read as smooth gyroid struts, not faceted chords.
  Params: period, strut diameter, **node-ball** size (sphere at junctions),
  **taper** (uniform / hourglass / bone), **cross-section** (round / triangular /
  star — area approximation), and a **density gradient** (smaller cells = stiffer,
  by Z or radially).

### Gyroid-matched shells
Beyond the perforated patterns below, the shell can **continue the interior
gyroid**:
- **Gyroid-matched (flowing)** — the shell perforation follows the gyroid
  surface band, so the wave pattern flows from infill onto the skin.
- **Node shell** — punches a hole at each point a skeletal strut reaches the
  surface, so struts visibly terminate at the wall.

### TPE-optimized G-code export
Every TPE-relevant knob is exposed (defaults shown):
- Print speed **20 mm/s**, travel **150 mm/s**, temp **220 °C**
- Retraction **1.5 mm @ 25 mm/s**, Pressure Advance **K=0.05**, Z-hop **0** (off)
- Base/bridge fan, line width, layer height, filament Ø, flow

Custom anti-stringing + surface-quality logic in `GCodeWriter.js`:
- **Continuous loops, one seam** — every wall/shell ring prints as a single
  uninterrupted extrusion (not chopped segments), so no per-segment blobs
- **Seam control** — aligned (hidden at the rear), nearest, or random
- **Coast** — extrusion stops for the last fraction of a loop so residual
  pressure closes the seam cleanly without a zit
- **Outer wall last & slower** — within each Z band, inner perimeters print
  first and the visible skin prints last at a dedicated *outer-wall speed*
- **Per-strut classification** — near-horizontal lattice struts and shell ring
  bands that span open windows print at **reduced speed + full fan + extra
  retract** (bridging); vertical struts/ribs use the normal profile
- **Wipe before travel** — a lateral smear back along the finished path
- **Nearest-neighbor path ordering** within bottom-up Z bands (loops/ribs are
  never shattered)
- **Combing** on short hops; **forced retract + lift across open grid windows**
- **First-layer profile** — own speed + fan for adhesion
- **Acceleration / jerk** smoothing on the visible skin (`M204`/`M205`)
- **Z-hop** and **Pressure Advance** (`M572`) support
- **Prusa XL start/end G-code** (heat, home, mesh level, prime line, present)
- Relative extrusion (`M83`); flow baked into per-move `E` values

> Existing TPE defaults (temp 220 °C, 20 mm/s, PA K=0.05, 1.5 mm retract, etc.)
> are kept as specified — calibrate Pressure Advance for your TPE before relying
> on the anti-stringing behaviour.

## Run locally

It's a static site, but ES modules require an HTTP origin (not `file://`):

```bash
# any static server works, e.g.
python -m http.server 8080          # then open http://localhost:8080
npx serve .
```

On Windows without Python/Node, a dependency-free PowerShell server is included:

```powershell
powershell -ExecutionPolicy Bypass -File serve.ps1 -Port 8123
# then open http://localhost:8123
```

Test models are included: `test/cube_40mm.stl` and `test/cylinder_d50_h60.stl`
(a curved surface, good for checking the perforated shell).

## Deploy to GitHub Pages

1. Push this folder to a GitHub repo.
2. **Settings → Pages → Build and deployment → Source: _Deploy from a branch_**,
   pick your branch and `/ (root)`.
3. The included `.nojekyll` file ensures the `js/` folder is served as-is.
4. Visit `https://<user>.github.io/<repo>/`.

Three.js is loaded from a CDN via an `importmap` in `index.html`, so there is
nothing to build or bundle.

## Architecture

```
index.html            UI + importmap (Three.js from CDN)
css/styles.css         3-panel dark UI (LEITZ green accent)
js/
  main.js              orchestration, UI events, live preview, view layer, presets
  STLParser.js         binary + ASCII STL -> positions
  MeshUtils.js         bounds, volume, accelerated point-in-mesh test
  PathUtils.js         the unified "path" print primitive + helpers
  LatticeGenerator.js  cubic / BCC / FCC / gyroid, clipping, caps, merge, colour modes
  ShellGenerator.js    perforated + textile skins (rib/mesh/auxetic/voronoi/hex/gyroid/node) + merge
  WovenSurface.js      true 3-D woven skin (interlacing warp + weft strands)
  Forms.js             parametric cushion forms (disc / oval / rectangle)
  Printability.js      per-pattern printability meter (pure, params-only)
  ObjExporter.js       toolpaths -> filament-bead tube OBJ (KeyShot render)
  GridShell.js         legacy grid shell (kept on disk; no longer wired)
  Slicer.js            planar contour extraction + arc-length helpers
  Gyroid.js            TPMS field + Marching Cubes
  marchingCubesTables.js
  GCodeWriter.js       surface-quality TPE G-code + PA tuning-tower generator
  PresetManager.js     presets, printability check, tooltips
  Renderer.js          Three.js scene / viewport (opacity, clip plane, colour, spin)
```

Everything the renderer and G-code writer consume is a **path**
(`{pts, kind, role, area, closed, bridge}`); a lattice strut is just a
2-point open path, a shell wall arc or ring a closed/open path. Printing closed
paths continuously is what gives clean, single-seam surfaces.

### Extending it
- **New lattice type:** add a `build…Struts()` builder in `LatticeGenerator.js`
  and a case in `generateLattice()`. Emit paths via `makeSeg(a,b,'lattice',...)`.
- **New shell pattern:** add a branch in `ShellGenerator.field()` returning the
  signed wall/hole scalar; run-extraction, merge, ordering, seam, coast are reused.
- **New colour mode:** add a branch in `LatticeGenerator.colorForMode()`.
- **New G-code behaviour:** the per-path loop in `GCodeWriter.generateGCode()`
  is the single place where speed/fan/retract/accel decisions are made.

## Notes & limitations
- **Hybrid printing model:** the lattice prints as direct 3-D struts
  ("wireframe"), while shells/walls print as planar continuous loops. This is
  what enables both the per-strut anti-stringing logic *and* clean shell
  surfaces. It is **not** a general-purpose planar slicer for solid bodies —
  those should still go through PrusaSlicer.
- Point-in-mesh clipping and contour slicing assume a reasonably **watertight**
  STL (a warning is shown if a requested shell produces no contours).
- The hole field is parameterised in a reference (arc, height) plane, so holes
  stay vertically coherent on prismatic/curved parts; on strongly **tapered**
  parts the column count is fixed from a mid-height reference and holes may read
  as uneven near the narrow end.
- **Lattice-matched** looks most integrated when the hole pitch ≈ the lattice
  cell size; the merge weld still connects struts to the skin for any pattern.
- Node-ball blends are flat in-plane micro-loops, not true 3-D fillets.
- Stats (grams, stringing-risk, hole-area %) are **estimates/heuristics**.
- Infill-density ↔ strut-diameter linkage is a first-order volume estimate.
- Gyroid is **experimental** (Marching Cubes resolution capped for speed).
- Shell slicing is capped at ~1200 layers; very tall parts get a coarser shell
  (a status note is shown) rather than freezing.

- The **skeletal gyroid** net is extracted numerically (field local maxima),
  so node degree is ≈3 (not guaranteed exactly 3) and the net is tuning-
  sensitive; non-round **cross-sections** are area approximations on a round
  centreline, not faceted toolpaths.
- The **node shell** is mostly-solid with holes only where struts reach the
  surface — raise *hole density* for a more open look on small parts.

- **Textile feature widths** below *min wall* are pruned by the printability
  guard (`closeTinyRuns`) — for Micro-Rib / fine mesh, lower *min wall* to ~0.5
  (the textile presets already do). The meter flags features below 1.5× nozzle.
- True **3-D relief** patterns (bubble domes, scale armor, cable knit, flyknit,
  raised jersey loops) and **per-face engineered zones** are out of scope for a
  single-wall planar slicer — documented, not faked.
- The **3D woven** skin uses a radial-from-centroid normal and weaves the largest
  loop per slice — ideal for the convex wearable forms; on strongly concave or
  multi-loop cross-sections the over/under separation degrades (true contour
  normal + multi-loop weave is on the backlog).

### Deferred (backlog)
Per-type G-code refinements (sheet continuous-path stitching, curvature-variable
speed, skeletal steep-first ordering, node-ball slow/low-flow), the *wave* shell
+ reinforcement rings + proud/recessed strut terminations, sheet
curvature/channel preview colouring, channel-connectivity (sealed-pocket) check,
Schwartz-P lattice, and Web Workers are scoped as follow-ups — current
synchronous generation stays responsive behind the debounce + busy overlay.

Always preview generated G-code before printing, and calibrate Pressure Advance
for your specific TPE (use the built-in PA tuning tower).
